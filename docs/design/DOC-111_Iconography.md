# DOC-111 — Iconography

**Document ID:** DOC-111  
**Title:** Iconography  
**Version:** 1.0  
**Status:** Approved  
**Owner:** Product & Design

---

# 1. Purpose

This document defines the icon system used throughout the ARCHIVE platform.

Icons are supporting elements.

They improve recognition, reduce cognitive load, and reinforce navigation.

Icons must never become decorative artwork.

---

# 2. Design Philosophy

Icons support content.

Typography communicates.

Photography inspires.

Icons clarify.

If removing an icon does not reduce usability, the icon should probably not exist.

---

# 3. Icon Library

The platform uses a single icon library across the entire product.

Approved library:

**Lucide**

No additional icon libraries should be introduced.

Mixing icon styles is prohibited.

---

# 4. Icon Style

Icons must be:

- Outline
- Minimal
- Geometric
- Consistent
- Neutral

Filled icons should only be used when explicitly documented.

---

# 5. Stroke

Default stroke width:

**1.75px**

Stroke width must remain consistent.

Do not manually modify stroke thickness.

---

# 6. Corner Style

Icons should use soft geometric corners.

Avoid:

- Sharp technical corners
- Cartoon styling
- Hand-drawn aesthetics

---

# 7. Default Size

| Usage | Size |
|--------|------|
| Small | 16px |
| Default | 20px |
| Large | 24px |
| Hero | 32px |

20px should be the default size across the application.

---

# 8. Color

Icons inherit text color.

Primary

#111111

Secondary

#4F4F4F

Muted

#8A8A8A

Disabled

#BEBEBE

Icons must never introduce new colors.

---

# 9. Alignment

Icons align to the text baseline whenever paired with text.

Maintain consistent spacing between icon and label.

Recommended spacing:

8px

Icons should never appear visually detached from labels.

---

# 10. Navigation Icons

Navigation icons support recognition.

Every navigation item should contain:

- Icon
- Label

Avoid icon-only navigation except where space is limited.

---

# 11. Action Icons

Action icons should communicate common operations.

Examples:

Search

Filter

Share

Edit

Delete

Bookmark

Favorite

Upload

Download

Settings

Users should recognize these instantly.

---

# 12. Status Icons

Status icons communicate state.

Examples:

Success

Warning

Error

Information

Pending

Verified

Status icons should always be accompanied by text where clarity is important.

Never rely on icons alone.

---

# 13. Decorative Icons

Decorative icons are prohibited.

Icons must always communicate meaning.

If an icon serves no functional purpose, remove it.

---

# 14. Product Information

Avoid excessive icon usage inside product cards.

Examples such as:

Size

Condition

Shipping

Location

should primarily rely on typography.

Icons should be introduced only when they improve scanning.

---

# 15. Buttons

Icons inside buttons are optional.

Use icons only when they improve recognition.

Examples:

+ Create Listing

Search

Share

Upload

Do not place icons inside every button by default.

---

# 16. Input Fields

Input icons should be limited.

Recommended uses:

Search

Password visibility

Calendar

Location

Avoid decorative leading icons.

---

# 17. Badges

Icons inside badges should remain rare.

Use only for universally understood concepts.

Examples:

Verified

Premium

Official

New

Avoid unnecessary visual complexity.

---

# 18. Empty States

Icons may replace illustrations for simple empty states.

Preferred size:

48–64px

Use muted colors only.

Icons should support the message—not dominate it.

---

# 19. Interactive States

Hover

Small color transition only.

Active

Subtle emphasis.

Disabled

Reduced opacity.

Avoid rotating or scaling icons during interaction.

---

# 20. Animation

Icons should remain static.

Exceptions:

Loading

Expand / Collapse

Chevron rotation

Sorting direction

Animations must remain subtle.

---

# 21. Accessibility

Icons used as interactive controls must include accessible labels.

Decorative icons should be hidden from assistive technologies.

Icons must never be the only indicator of meaning.

---

# 22. Consistency

The same concept must always use the same icon.

Examples:

Heart → Favorites

Bookmark → Saved

Bell → Notifications

Settings → Preferences

Avoid using multiple icons for the same action.

---

# 23. Forbidden Practices

Do not:

- Mix outline and filled styles
- Stretch icons
- Rotate icons unnecessarily
- Apply gradients
- Apply shadows
- Apply glow effects
- Use emojis as interface icons
- Replace text with icons where clarity suffers

---

# 24. AI Implementation Rules

AI tools must use only the approved icon library.

Icons must remain consistent in style, size, stroke width, and behavior.

Do not substitute similar icons without a documented reason.

---

# 25. Definition of Success

Icons should become almost invisible to experienced users.

They should quietly improve recognition and navigation without drawing attention to themselves.

Users should remember what they accomplished—not the icons they clicked.
